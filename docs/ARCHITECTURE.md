# 架构与验证

```text
Codex 文件入口
  → MCP 插件取得宿主文件路径 + 当前内容哈希
  → 本机保存服务创建绑定原文件的会话
  → Codex 内置浏览器打开 https://localhost:43233/editor/…
  → ONLYOFFICE（独立 Lima VM，无主机目录挂载）
  → 签名回调导出至本机版本目录
  → 用户点击保存：冲突检查、备份、写回原文件
```

源码和运行数据分开；安装生成的 MCP 配置会自动使用使用者当前 Node 路径及源码位置。0.5.0 安装器自动复制运行源码到应用数据目录，下载目录不再是运行依赖。此方案不是远程云编辑，也不是纯前端编辑器。

本次可重复自动测试：三种格式的存储绑定、后台重新载入后保存、备份、外部冲突、签名验证、回调地址限制、缺少宿主路径时拒绝、安装 dry-run 不产生数据、安装配置可迁移、发布允许列表扫描。

开发机已验证的交互：完整 ONLYOFFICE 中 Word 修改文本，Excel 修改单元格，PPT 新增幻灯片；写回原文件，再次打开保留修改；保存不依赖中间页；三种文件通过 Codex 菜单选择后记住默认打开。

未验证：第二台干净 Mac 的完整安装、所有 macOS/Codex 版本、Windows/Intel Mac、全部 Office 功能、大型复杂文档保真。CI 只运行组件检查，不创建 VM，不改变钥匙串，不代表这些未验证项通过。

发布前安装检查：在开发 Mac 的独立新虚拟环境安装引擎，验证服务启动、按本机证书校验的 HTTPS 连接，以及 DOCX/XLSX/PPTX 的真实引擎转换、签名回调和原文件写回。第一次安装的可选插件下载耗时过长，测试中停止了该下载；发行安装器已改用官方 `onlyoffice/plugins-enabled=false` 选项跳过它。没有向开发机钥匙串添加测试证书；因此这不是第二台电脑上的无人工介入安装验收。

0.5.0 安装验证：在 PATH 不含 Homebrew 的独立测试目录中，真实下载并校验官方 Node/Lima，使用 macOS 自带 LibreSSL，自动复制应用、安装 npm 依赖、复用独立测试虚拟机、启动服务，并通过锁定版本 Codex CLI 在隔离的 CODEX_HOME 中完成插件注册；重试会复用已下载环境。新版安装后的三种格式引擎转换、签名回调和原文件保存也已复核。测试没有添加系统证书信任，未验证另一台 Mac 的 Gatekeeper 首次放行。
